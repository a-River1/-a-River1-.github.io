# How API works:
The point of the project is to used information form a variety of APIs to accomodate a specific legal request, whether an individual wants to know if he has grounds for something, or (more likely), in a paralegal sense, in that it collects informationf or a court case such as precedent.  The backend uses json modules to call the APIs in which OpenAI is responsible for translating back and forth (translating inputted and outputted information).  CourtListener searches a databank of court cases using specific key words from OpenAI API to find related and important information.  GovInfo and OpenStates do the same but for searching specifical U.S. federal codes and state codes.  For each API (excluding OpenAI), simply creating an account on their individual websites is enough to recieve an API key as it is immedietly offerd to you.

# Paralegal research workspace

A local US legal research app in Paralegal.html, with a Python backend that keeps credentials out of the browser.

## Run

Python 3.11+ is the only runtime requirement. No third-party packages are needed.

1. Save all four keys in the ignored .env file, one entry per line:
   OPENAI_API_KEY, COURTLISTENER_API_KEY, GOVINFO_API_KEY, OPENSTATES_API_KEY.
2. From this repository run:

   python paralegal_server.py

3. Open http://localhost:8000/Paralegal.html.
4. Describe the underlying claim, select a state, add county/court and context, and build a packet.

The server rereads .env for each request. Use Refresh configuration after saving changes. “Configured” means a nonempty key is present, not that provider access has been verified. Missing providers are reported separately; OpenAI is required for planning and synthesis. Open States is explicitly skipped until a state is selected.

Use --port 8001 if port 8000 is occupied. OPENAI_MODEL can override the default gpt-5.5 with an available model supporting Responses, structured outputs, and web search.

## What the app does

- OpenAI creates short topic queries (instructed to omit personal identifiers).
- CourtListener searches published case law and retrieves the leading opinion text when available.
- GovInfo searches USCODE, CFR, PLAW and USCOURTS, retrieving HTML text where available.
- Open States searches bills within the selected state, with abstracts and action history.
- OpenAI web search supplements these databases with official state/local law and legal-aid resources.
- OpenAI summarizes retrieved evidence into a packet with source IDs, relevance, jurisdiction caveats, contrary authority, missing facts and next steps.
- Document annotations are shown only when their quoted text exactly matches retrieved source text. Research notes generated by web search are never treated as original-document quotes.
- Source filters, expandable text with highlights, JSON export, and print/save-to-PDF support review.

A search usually makes three OpenAI calls (query planning, web research, synthesis), one search per configured legal database, and up to four document retrievals each for CourtListener and GovInfo. API charges and provider access restrictions apply. There is no automatic paid-request retry or key rotation.

## Evidence and scope limitations

This is a research aid, not legal advice or a citator. A licensed attorney should verify all legal conclusions and applicability.

- Exact quote matching verifies text presence only, not meaning or current good-law status.
- Cases are not automatically restricted to the selected jurisdiction; summaries are instructed to explain authority and jurisdiction. Cross-jurisdiction results may be useful or irrelevant.
- Open States bills are not a complete corpus of current codified state law. Passage, enactment, effective dates, later amendments and local law require verification.
- Text retrieval is capped at the first 24,000 characters per document; each card discloses full text, truncated text, snippets or metadata. Missing text is never silently presented as full text.
- Search results are limited to four per database and up to ten supplemental web sources. No exhaustive-coverage or good-law guarantee.
- Annotated documents are HTML/text passages in the research packet, with links to originals. The app does not modify original court PDFs or retrieve sealed/PACER-only filings.
- Provider failures are displayed individually; a packet may therefore be incomplete. Empty searches produce no invented conclusions.

## Privacy and hosting

Keys stay in server memory and .env. The server serves only four explicit frontend routes and does not serve .env, .git, tests, or arbitrary repository files. It binds only to 127.0.0.1 and checks Host, Origin and a session token on paid requests. Only one research request runs at a time.

Prompts and context are transmitted to OpenAI. Search terms are sent to the legal-data providers and OpenAI web search. Remove confidential or identifying details before submitting; the model's instruction to omit identifiers is not a guaranteed anonymization system. OpenAI requests use store:false; this does not override providers' retention policies.

The app does not write prompts or results to disk and does not use browser localStorage. Downloaded/printed packets contain the facts submitted and should be handled appropriately. Your existing OneDrive folder may sync .env independently of Git; .gitignore is not encryption or a cloud-sync exclusion.

GitHub Pages serves static files and cannot run this backend. Opening Paralegal.html on Pages or using an ordinary static file server will show a setup message. Do not copy API keys into frontend code to make it work. Public hosting requires an authenticated HTTPS backend, secret environment variables, rate limits, and deployment-specific hardening; the bundled server is for local use.
